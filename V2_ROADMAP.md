# LifeTrack AI V2.0 Roadmap

**Status:** In progress  
**Release target:** 2.0.0  
**Release rule:** Keep the existing production version and APK unchanged until the V2 scope is implemented, tested, and deliberately released.

## Existing architecture and preservation baseline

- The hosted product is a vanilla HTML/CSS/JavaScript dashboard served as Cloudflare Worker assets. `worker/site/` is the hosted source; `worker/public/` is generated by `node worker/build-assets.mjs`. The root copies support the GitHub Pages entry point.
- User tracker data is stored per account in browser/app local storage and synchronized for Google sign-in users through a private Google Drive app-data JSON file. The Worker does not host a tracker database.
- The PWA uses a service worker for offline app-shell caching. The Android APK is a Java/Kotlin WebView wrapper with native reminders, Health Connect, and offline fallbacks. The desktop launcher opens the hosted app in a browser.
- Existing working areas include habits/check-ins and history, monthly goals, focus sessions, daily tasks, fitness and Android Health Connect, reminders, an AI assistant, analytics, badges, backups, and offline use.
- Keep account identity, saved tracker records, Google OAuth/Drive sync, Android permissions, and current deployment infrastructure intact. Do not label an unfinished local build as a production V2 release.

## Phases

1. **Foundation and Life Score (first increment delivered):** Document the architecture, add a transparent 0–100 score from real tracker data, allow per-category weights, avoid treating missing optional data or an uncompleted optional challenge as failure, and add tests.
2. **Dashboard and reports:** Add configurable dashboard widgets and useful weekly/monthly Life Score trends and exports, reusing current charts and habit history where they already meet the need.
3. **Habits, goals, focus, and coaching:** Close gaps in schedules/rest-day support, goal milestones/subtasks, completed-session history and targets, and AI progress reports. Keep AI outputs grounded in supplied data and require review before data-changing actions.
4. **Personalization and reliability:** Improve settings, reminder preferences, cross-device preference sync, offline conflict handling, data export/deletion, accessibility, performance, and security without replacing current storage or sync without a migration plan.
5. **Release readiness:** Test desktop/mobile layouts, existing user data, account and Drive sync, offline/reconnect, notifications, and an Android APK. Update public version metadata, build and test the APK, and deploy only after release checks and rollback preparation.

## Phase 1 implementation notes

The first increment adds the Life Score to the existing dashboard. Habits use today's completed check-ins; goals use real progress against their current monthly targets; focus uses completed LifeTrack focus minutes against a 30-minute target; wellness averages available recorded steps, water, sleep, and mood against the app's existing targets; the optional daily challenge counts only after completion. Missing optional readings are excluded from the weighted average, and exercise minutes are not a scoring category, so a rest day is not penalized for skipping a workout.

Category weights are saved in the current account's local device storage. Cross-device preference sync and historical score charts remain later-phase work. No existing tracker record is migrated or rewritten by this feature.
